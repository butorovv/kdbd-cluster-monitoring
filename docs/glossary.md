# Словарь терминов курса

Терминология курса следует учебнику **Новиков Б. А., Горшкова Е. А., Графеева Н. Г. Основы технологий баз данных. — 2-е изд. — М.: ДМК Пресс, 2020**
(свободно доступен: https://postgrespro.ru/education/books/dbtech) и переводам К. Дейта. Английский термин — в скобках, он встретится в документации.

## Реляционная модель

| Термин на курсе | Что это | English |
|---|---|---|
| отношение / таблица | набор кортежей одной схемы; в SQL — таблица | relation / table |
| атрибут / столбец (колонка) | именованный компонент отношения | attribute / column |
| кортеж / строка | одна запись отношения | tuple / row |
| домен | множество допустимых значений атрибута | domain |
| схема базы данных | описание структуры данных, хранимое в самой БД | database schema |
| логическая схема, схема хранения, внешняя схема | три уровня модели ANSI/SPARC | conceptual / internal / external schema |
| ограничение целостности | условие, которое СУБД проверяет при каждом изменении | integrity constraint |
| согласованность | корректность данных с точки зрения приложения; поддерживается транзакциями | consistency |
| неопределённое значение | NULL: значение не известно или не имеет смысла | null value |
| дубликаты | одинаковые строки, допустимые в SQL, но не в теории | duplicates |
| проекция, фильтрация, соединение | операции реляционной алгебры | projection, selection, join |
| эквисоединение, внешнее соединение | соединение по равенству; соединение, сохраняющее строки без пары | equijoin, outer join |

## Ключи и зависимости

| Термин на курсе | Что это | English |
|---|---|---|
| функциональная зависимость X → Y | зная X, однозначно знаем Y | functional dependency |
| возможный ключ (потенциальный ключ) | набор атрибутов, от которого зависят все остальные | candidate key |
| минимальный ключ | возможный ключ, из которого нельзя убрать ни один атрибут | minimal key |
| первичный ключ | выбранный минимальный ключ | primary key |
| естественный ключ | ключ из атрибутов предметной области (код агрегата) | natural key |
| суррогатный ключ | искусственный идентификатор, порождённый системой | surrogate key |
| составной ключ | ключ из нескольких атрибутов | composite key |
| внешний ключ | ссылка на ключ другой таблицы | foreign key |
| справочник | таблица допустимых значений (уровни серьёзности, типы датчиков) | lookup / reference table |
| таблица связи (ассоциативная сущность) | таблица, реализующая связь «многие ко многим» | junction / associative table |

## Нормализация

| Термин на курсе | Что это | English |
|---|---|---|
| аномалия вставки / обновления / удаления | нежелательный эффект избыточности | insertion / update / deletion anomaly |
| избыточность | один факт хранится несколько раз | redundancy |
| частичная зависимость | неключевой атрибут зависит от части ключа | partial dependency |
| транзитивная зависимость | X → Y и Y → Z | transitive dependency |
| 1NF, 2NF, 3NF, BCNF | первая, вторая, третья нормальные формы; нормальная форма Бойса — Кодда | normal forms |
| денормализация / избыточные структуры хранения | осознанное дублирование ради скорости чтения: избыточный столбец, материализованное представление | denormalization |

## Концептуальное моделирование

| Термин на курсе | Что это | English |
|---|---|---|
| модель «сущность — связь» | концептуальная модель: сущности, атрибуты, связи | entity — relationship (ER) model |
| диаграмма «сущность — связь» | её графическое представление | ER diagram |
| множество сущностей / сущность | класс объектов / его экземпляр | entity set / entity |
| связь, кардинальность связи | 1:1, 1:N, M:N | relationship, cardinality |
| нотация «воронья лапка» | обозначения кардинальностей на диаграмме | crow's foot notation |

## Транзакции и хранение

| Термин на курсе | Что это | English |
|---|---|---|
| транзакция | набор операций, переводящий БД из одного согласованного состояния в другое | transaction |
| атомарность, согласованность, изоляция, долговечность | свойства ACID | ACID |
| аномалии конкурентного выполнения | потерянное обновление, грязное/неповторяющееся чтение, фантомы | concurrency anomalies |
| уровень изоляции | компромисс между строгостью и производительностью | isolation level |
| журнал транзакций, контрольная точка | средства восстановления после отказа | write-ahead log, checkpoint |
| индекс | избыточная структура для ускорения поиска | index |
| план запроса, оптимизатор | как СУБД выполняет запрос и кто это решает | query plan, optimizer |
| материализованное представление | заранее вычисленный и сохранённый результат запроса | materialized view |
| общее табличное выражение, оконная функция, рекурсивный запрос | средства SQL недели 3 | CTE, window function, recursive query |
| миграция схемы | пронумерованное изменение схемы, применяемое один раз | schema migration |
| репликация, согласованность реплик, разделение сети | распределённые данные (неделя 7) | replication, replica consistency, network partition |

## SQL для анализа данных (лекция 3)

| Термин на курсе | Что это | English / SQL |
|---|---|---|
| внутреннее / внешнее соединение | только пары с совпадением / плюс строки без пары, дополненные NULL | inner / outer join |
| перекрёстное соединение | все пары строк (декартово произведение) | cross join |
| полусоединение / антисоединение | есть ли хоть одна пара / нет ни одной пары | semi-join / anti-join; EXISTS / NOT EXISTS |
| коррелированный подзапрос | подзапрос, ссылающийся на строку внешнего запроса | correlated subquery |
| подзапрос LATERAL | подзапрос в FROM, который видит столбцы таблиц слева | LATERAL |
| агрегатная функция с фильтром | агрегат только по строкам, удовлетворяющим условию | FILTER (WHERE …) |
| наборы группирования | несколько группировок в одном запросе: подытоги и итог | GROUPING SETS, ROLLUP, CUBE |
| упорядоченная агрегатная функция | медиана, процентили | percentile_cont … WITHIN GROUP (ORDER BY …) |
| общее табличное выражение (ОТВ) | именованный подзапрос перед основным запросом | common table expression, WITH |
| оконная функция | значение по набору строк, приклеенное к каждой строке | window function, OVER (…) |
| раздел | группа строк, в пределах которой работает окно | partition, PARTITION BY |
| рамка окна | какие строки раздела видит функция относительно текущей | window frame, ROWS / RANGE |
| функции ранжирования и смещения | номер строки, ранг; значение соседней строки | row_number, rank, dense_rank; lag, lead |
| рекурсивный запрос | запрос, ссылающийся сам на себя; обход дерева и графа | WITH RECURSIVE |
| нерекурсивная и рекурсивная части, рабочая таблица | старт; шаг; строки, найденные на прошлом шаге | non-recursive / recursive term, working table |
| список смежности | дерево в таблице: у каждой строки — ссылка на родителя | adjacency list, parent_id |
| обнаружение циклов | остановка обхода графа при повторном посещении | CYCLE … SET … USING |

## Нереляционные модели

| Термин на курсе | Что это | English |
|---|---|---|
| слабоструктурированные данные | JSON, XML — данные со схемой «внутри» значения | semi-structured data |
| хранилище «ключ — значение» | простейшая модель: ключ и непрозрачное значение | key-value store |
| агрегатно-ориентированные БД | документные и колоночные семейства (MongoDB, Cassandra) | aggregate-oriented databases |
| базы данных на основе графов | узлы и связи как первичная структура | graph databases |
| временные ряды | измерения, упорядоченные по времени | time series |

## Предметная область учебного примера

| Слово в материалах | Что означает |
|---|---|
| площадка | место, где стоит оборудование (в датасете: Северная, Восточная, Южная) |
| агрегат | единица оборудования: компрессор К-1…К-4, насос P-1, P-2, воздушный охладитель COOL-1 |
| карточка оборудования | справочные данные: модель, дата ввода в эксплуатацию, состояние |
| датчик, код датчика (столбец tag) | TE — температура, VT — вибрация, PT — давление, LD — нагрузка |
| телеметрия | показания датчиков с отметкой времени |
| событие, уровень серьёзности | запись из системы управления: info / warning / alarm / unplanned_stop |
| заявка на ремонт, обслуживание | запись о выполненной работе на агрегате |
| SCADA | система сбора данных и диспетчерского управления — источник событий |
