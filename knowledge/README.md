# База знаний мониторинга кластера

Версия для оператора и инженера мониторинга. Программа читает топологию, оборудование, телеметрию и эксплуатационные записи из PostgreSQL. Вместе с ответом она показывает правило, условия, значения, первичные ключи строк и источники знаний.

## Запуск демонстрации

Из корня репозитория, при запущенном Docker и доступном Docker Compose:

```sh
make -C knowledge demo
```

Команда использует отдельный Compose-проект `cluster-kb-demo`, собственный том и внутреннюю сеть без опубликованного порта, применяет штатную миграцию `seminar02` и выводит JSON по всем десяти вопросам. Данные Summit из миграции синтетические. Сервисы учебных семинаров используют свои настройки и тома. Для остановки демонстрационного сервиса выполните `docker compose -p cluster-kb-demo -f knowledge/compose.yml stop`.

## Запуск без Docker

Потребуются локальные серверные утилиты PostgreSQL (`initdb`, `pg_ctl`, `createdb`, `psql`) и Python с установленным драйвером из `knowledge/kb/requirements.txt`. Команды используют временный экземпляр с Unix-сокетом и останавливают его после выполнения.

```sh
make -C knowledge demo-local PYTHON=/абсолютный/путь/к/python
make -C knowledge test-db-local PYTHON=/абсолютный/путь/к/python
```

## Запуск на существующей PostgreSQL

Если в учебном стеке ещё нет схемы проекта, примените штатную миграцию командами `make up` и `make migrate` после готовности PostgreSQL. Для имеющейся базы нужен доступ на чтение таблиц схемы `project`.

```sh
kb_venv="${TMPDIR:-/tmp}/cluster-kb-venv"
python3 -m venv "$kb_venv"
"$kb_venv/bin/python" -m pip install -r knowledge/kb/requirements.txt
cd knowledge
"$kb_venv/bin/python" -m kb Q09 --node a01n01 --at 2026-10-01T09:01:00Z
```

Перед запуском передайте `DATABASE_URL` через окружение. Подойдут DSN libpq и URI PostgreSQL. CLI принимает `Q01`–`Q10` или `all`. Снимок берётся на точный момент `--at`, с ISO 8601 и часовым поясом. Вопросы Q06 и Q07 показывают всю историю соответствующего узла. Поля PostgreSQL типа `numeric` передаются в JSON строками для сохранения точности. Учебный профиль `--demo-profile` включает условный предел GPU 80 °C. В обычном режиме подходящий подтверждённый предел отсутствует.

В объяснении `conditions` перечисляет условия выбранного правила, `rows` содержит строки или результат соединения из PostgreSQL, `knowledge` указывает записи каталога, а `suppressed` показывает совпавшие правила с меньшим приоритетом или более поздним ID. Отсутствующее значение, несовместимая единица и отсутствие подтверждённой нормы дают отдельные статусы.

## Пробные модели

Запускайте из корня репозитория. Для логической модели нужен `swipl` в `PATH`.

```sh
python3 knowledge/trial/production.py
swipl -q -s knowledge/trial/logic.pl
python3 knowledge/trial/check.py
```

Последняя команда сравнивает результаты обеих моделей с общим эталоном и проверяет десять ID по каталогу.

## Тесты и защита

```sh
make -C knowledge test PYTHON="${TMPDIR:-/tmp}/cluster-kb-venv/bin/python"
make -C knowledge test-db
```

Без `DATABASE_URL` выполняются тесты движка. При запуске интеграционных тестов вручную укажите DSN отдельной БД с демонстрационной миграцией. Добавьте `KB_TEST_MUTATE_DEMO=1` только для временной базы `cluster_kb_demo`, чтобы включить изменение измерения. `test-db` проверяет все десять ответов через CLI на PostgreSQL. Тест изменения измерения предназначен для изолированной БД `cluster_kb_demo`: он обновляет одно значение, повторно запускает CLI, восстанавливает исходное значение и проверяет восстановление ответа. Смотрите результаты `test_live_measurement_changes_cli_diagnosis` для перехода от 61 °C к ровно 80 °C. Для живого показа запустите `demo`, покажите Q02 и Q05, затем запустите `test-db` и разберите смену `R-BELOW` на `R-HOT`.
